# RSC_seoul '문헌록' 모듈 기획서 (PRD)

## 1. 개요
**RSC_seoul (서울 인적자원개발위원회 통합 리서치 플랫폼)**은 현장 전문가 인터뷰 및 포럼 녹취를 다루는 '현장록' 기능에 이어, 학술 논문, 실태조사, 정책 보고서 등 거시적/객관적 텍스트 데이터를 분석하는 **'문헌록'** 모듈을 신규 도입합니다.

## 2. 핵심 목표
1. **정형 데이터 자산화:** 방대한 텍스트로 이루어진 PDF/Word 형식의 연구보고서, 논문 등을 구조화된 JSON 데이터(문헌록)로 파싱하여 플랫폼 내에 저장합니다.
2. **2-Tier 분석:** 
   - Tier 1: 객관적 서지 정보 및 방법론 팩트 추출.
   - Tier 2: 연구의 핵심 질문(Research Question)을 중심으로 정책적, 실무적 시사점을 유연하게 추출.
3. **서울지역 특화 정책 제안:** 분석된 문헌 내용을 바탕으로 서울시 고용 시장, 산업 특성(서비스, SW, 바이오 등)에 맞는 액션 아이템 및 NCS(국가직무능력표준) 연계 방안을 AI가 제안합니다.
4. **통합 자료실 교차 검증 연계:** '현장록' 모듈의 인터뷰 데이터와 '문헌록' 모듈의 실증 데이터를 '통합 자료실'에서 서로 교차 검색하고 분석(하이브리드 교차 검증)할 수 있는 인프라를 완성합니다.

## 3. 타겟 유저
*   **리서처 / 연구위원:** 대량의 정책 보고서나 논문을 빠르게 훑어보고 서울 지역에 맞는 정책적 인사이트를 도출해야 하는 담당자.
*   **HRD 정책 기획자:** 특정 산업군의 훈련 수요(현장록)와 관련 선행 연구(문헌록)를 교차로 확인하여 새로운 교육훈련 과정을 기획해야 하는 실무자.

## 4. 유저 스토리 (User Stories)
*   **US1 (문헌 업로드):** "연구원으로서, 나는 PDF 형태의 산업 실태조사 보고서를 시스템에 업로드하여 AI가 알아서 서지 정보와 핵심 방법론을 뽑아주길 원한다."
*   **US2 (맞춤형 포커스):** "연구원으로서, 나는 문헌을 업로드할 때 '청년층 미스매치 관점에서 분석해 줘'라는 포커스 질문을 던져 그에 맞는 시사점만 골라내길 원한다."
*   **US3 (시사점 및 액션 도출):** "정책 기획자로서, 나는 요약된 문헌 내용이 서울시 일자리 거버넌스나 NCS 훈련과정과 어떻게 연결될 수 있는지 구체적인 아이디어를 얻고 싶다."
*   **US4 (교차 검증):** "리서처로서, 나는 통합 자료실에서 이 문헌의 결론이 이전에 업로드된 '중소기업 대표 인터뷰(현장록)' 결과와 얼마나 일치하는지 비교 분석하고 싶다."

## 5. 핵심 기능 (Features) & 아키텍처

### 5.1. 문헌 데이터 업로드 및 파싱
*   **UI:** `/literature/upload` (문헌록 전용 업로드 페이지)
*   **기능:** PDF, 텍스트 복사/붙여넣기, 외부 링크(URL) 등을 통해 원문을 입력받습니다.
*   **추가 입력 필드:** 사용자가 직접 지정하는 집중 분석 질문(`focus_questions`) 입력란 제공.

### 5.2. 2-Tier AI 분석 엔진 (Gemini 2.5 Pro Interactions API)
*   제공된 파이썬 스크립트 기반의 시스템 프롬프트를 TypeScript 환경에 맞게 이식합니다 (`@google/genai` Interactions API 활용).
*   **Tier 1 (Grounding):** `document_metadata` (서지 정보) 및 `methodological_framework` (연구 방법론) 추출.
*   **Tier 2 (Question-Centric):** `question_driven_analysis` (연구 질문 중심 분석) 추출. 
*   **Policy Synthesis:** `seoul_hrd_insights` (서울 특화 시사점 및 NCS 연계) 제안.
*   **출력:** 완벽히 구조화된 JSON 스키마를 반환.

### 5.3. 문헌록 조회 및 통합 DB 구조
*   **UI:** `/literature/$id` (개별 문헌록 상세 조회 페이지). 추출된 JSON 데이터를 아름다운 마크다운 및 카드 레이아웃으로 렌더링.
*   **DB (Firestore):** 
    *   기존 `sessions` 컬렉션과 분리된 `literatures` 컬렉션 생성 (또는 기존 프로젝트 하위에 `literatures` 하위 컬렉션 구성).
    *   통합 자료실 검색을 위해 문헌록 데이터도 텍스트 임베딩(Vector DB) 처리 파이프라인 연결 필요.
